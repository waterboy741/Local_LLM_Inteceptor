# M4 offline network helper

The network module is an offline integration layer with a validated command dispatcher. It has no concrete macOS mutation backend, helper executable, installed privileged service, or GUI activation path. Existing application launch and Observe/Modify workflows remain the explicit local proxy. `SystemOperations` is injected in tests; every network readiness result and mutation result is synthetic. No PF rules, settings, neighbors, or captures were changed for M4.

## Snapshot and routing contract

`SessionSnapshot::create` is the only constructor for a valid snapshot. It copies the configured interface, client IPv4, server IPv4/port/API paths, research host IPv4/MAC, peer MACs, subnet, proxy endpoint evidence, and session ID. Callers can change their original configuration afterward without affecting an active session.

Preflight rejects missing authorization/readiness, unverified dedicated anchor attachment, proxy upstream/listener mismatch, different interfaces, invalid or identical IPv4/MAC addresses, multicast/zero MACs, loopback/routed/IPv6 peers, subnet network/broadcast addresses, and unsupported prefixes outside /1–/30. The same numerical TCP port for loopback proxy and remote server is valid. Interface names use a strict allowlist and quoted PF token; session IDs are limited to 48 alphanumeric/underscore/hyphen characters. Every IPv4 and port rendered into PF is validated and canonical. Readiness flags default false.

These facts are **injected evidence**, not actual verification. A future backend must revalidate authorization, interface/link/neighbor state, dedicated active anchor attachment, and the exact listening proxy/upstream route when acquiring the session lease. A stale factory result cannot authorize live activation.

PF redirection matches only incoming selected-interface IPv4 TCP from the client to the selected server port. It redirects to the selected loopback proxy port; a translated local-delivery filter allows the same client. Pair-scoped bypass filters support other attracted traffic; the independent proxy upstream filter allows the research source to the selected server/port. The research source cannot match the client redirection rule. Proxy readiness IP/port/listener evidence must exactly match the snapshot, and `snapshot.config()` supplies the upstream configuration.

The application anchor is `llm_interceptor/<session-id>` and rules carry a session label. Installing an anchor without an active translation/filter attachment point is insufficient. `rdr-anchor "llm_interceptor/*"` and filter evaluation must be provisioned without replacing global rules or appropriating Apple's namespace. Active attachment, ordering, skip rules, and coexistence remain M6 validation.

`PfDiagnostics::collectPreInstallReadiness` is an offline, read-only preliminary probe. It runs only fixed PF status, main filter-rules, and main translation-rules queries, stopping at the first failed or unrecognized result. It requires PF enabled and exactly one recognized `anchor "llm_interceptor/*"` and `rdr-anchor "llm_interceptor/*"` reference in the corresponding main rules. The result omits raw command output and session details. These are observed textual references only: they do not prove that a session anchor exists, that PF evaluates the anchor, or that traffic is redirected. The probe is not wired into the GUI, CLI, or mutation adapter, and tests use only an injected fake runner.

## M6 scoped PF operation adapter (offline only)

`PfAnchorOperations` converts an existing immutable `SessionSnapshot` into only two fixed command plans: load that snapshot's generated rules with `/sbin/pfctl -a llm_interceptor/<session-id> -f -`, or remove that same anchor's rules with `/sbin/pfctl -a llm_interceptor/<session-id> -F rules`. Install rules are passed as stdin; neither command invokes a shell. `QProcessPfAnchorCommandRunner` now provides a concrete macOS-only runner for those typed commands. It rechecks the exact program, arguments, owned-anchor shape, stdin constraints, and fixed 3-second command deadline/64-KiB output cap before launching. The combined bytes drained are capped at 64 KiB plus a one-byte overflow sentinel; Qt may transiently buffer more output internally between drain events, so this is not a hard process-memory bound. Timeout, observed output overflow, or write failure triggers child termination and a bounded reap attempt of up to one additional second. An unreaped child is reported as failure with process uncertainty retained, and raw output is discarded. Tests inject a typed child-process factory and do not execute `pfctl`. The runner remains unwired to the GUI, CLI, or `SystemOperations`.

Before installation reaches the runner, the adapter requires an effective-root check, a nonempty current session lease, confirmation that PF is enabled, fresh verification of the main filter and translation attachment references, and lease-bound proof that the session anchor is safe to create or replace. It also requires the snapshot's anchor-preflight bit; this injected bit alone never satisfies fresh attachment verification. Removal requires effective root, the current lease, and proof that this exact anchor belongs to that lease; it does not require PF to remain enabled or the global attachment to remain present, so scoped cleanup can still be attempted after partial startup or attachment loss. The authorization provider must reject an existing unowned/colliding anchor. `-F rules` is scoped by `-a` to this exact owned anchor; no global flush, global attachment install, PF enable, or state-table flush is available.

Once a runner reports that the command started, every error, timeout, output-limit failure, permission failure, or nonzero exit has `mayHaveApplied=true`. The caller must journal ownership before the attempt and retain/retry cleanup when it fails; a failed command result does not prove that PF remained unchanged or that cleanup succeeded. These plans do not establish packet evaluation, actual redirection, or live support. A concrete macOS authorization provider, attachment/ownership verifier, runner integration, and recovery integration remain unimplemented.

`redirectionFrames()` generates two targeted ARP replies using the research MAC in the ARP sender field, one per peer. `restorationFrames()` generates targeted replies restoring each peer's actual neighbor MAC. Neither method sends a frame. `ArpCodec` supports Ethernet/IPv4 ARP requests/replies, validates fixed header sizes before reads, rejects truncation/unsupported types and VLAN frames, and tolerates Ethernet padding. Encoded frames are padded to 60 bytes excluding FCS. Corrective frames and Wi-Fi/AP acceptance remain unproven in M6.

## Offline authorization boundary

`HelperDispatcher` owns one frozen permitted snapshot, trusted peer UID/audit identity, and an opaque session capability. `dispatch` receives verified peer credentials separately from command data. Default/unverified peers fail closed. Start requires the full matching snapshot; heartbeat, watchdog, and stop cannot supply replacement configuration. Every command must carry the exact session anchor and capability. Successful stop, watchdog cleanup, or startup rollback to Idle makes the dispatcher terminal and revokes the capability; a new authorization/dispatcher is required to start again. CleanupPending keeps the capability usable for authorized Stop retries. Unknown commands, malformed arguments, wrong peer/token, changed targets/MACs/API paths, and invalid clock values are rejected before any system operation.

`HelperWatchdog` adds an offline `QTimer` scheduler that observes dispatcher state and runs only while the session is Active. Its callback is private to the dispatcher/watchdog pair and receives no peer identity, command, or capability. `HelperDispatcher` owns the trusted monotonic clock callback; socket transport and scheduled ticks both query that exact callback, so their time source cannot drift apart. Missing, throwing, negative, or regressing time fails closed. Invalid timer intervals use the safe 250 ms default. The timer is owned by the scheduler, and timer/session operations run on their owner thread; it stops when cleanup starts or the dispatcher is destroyed. This timer can check independently of GUI/IPC callbacks only while hosted in a running Qt event loop; no installed, surviving helper service or live watchdog behavior is claimed.

This is an offline authorization model with a borrowed-socket transport primitive, not a deployed or complete IPC service or cryptographic protocol. Tests inject synthetic verified peers and capabilities. A production local service must obtain OS-verified identity/audit credentials independently of request bytes, securely issue/distribute session capabilities, bind them to the active session, and enforce signing/installation policy. No generic execute-command, arbitrary sysctl, or global PF flush operation exists in the dispatcher. The production listener, capability persistence, and signing/installation implementation remain M6. Capability comparison in this offline model uses QByteArray equality; constant-time secret validation and secure issuance/distribution are production transport requirements, not claimed here.

## M6 Unix-socket credential primitive

`verifiedPeerForUnixSocket()` derives the peer UID/GID from a connected Unix-domain socket using `getpeereid` on macOS and `SO_PEERCRED` on Linux. `dispatchOneUnixSocketCommand()` requires a connected Unix `SOCK_STREAM` socket and adds a one-request transport with a four-byte length prefix, a 256-byte frame limit, a one-second total request deadline, and a fixed binary allowlist for Heartbeat and Stop. The client must half-close its send side after the frame; the parser waits for EOF and rejects any trailing bytes before dispatch. It derives command time from the trusted monotonic clock callback owned by `HelperDispatcher`; clients cannot submit timestamps, snapshots, peer identity, or Watchdog/Start commands. The parser rejects invalid lengths, unsupported versions/commands, malformed capabilities/anchors, and trailing request bytes before dispatch. A separate one-second bounded response is one byte indicating dispatcher acceptance. If dispatch succeeded but the response fails, the caller receives an error stating the command may have applied. The caller supplies an already accepted socket and is responsible for its listener/lifecycle.

The returned dispatcher identity is only the kernel-reported UID/GID tuple. Processes running as the same UID are not distinguished, and this does not verify an executable, code signature, or audit token. A privileged service must enforce the intended signing/installation policy separately. Safe Start snapshot/capability bootstrap, an installable/surviving helper service, a listener, a concrete system backend, and privileged operations remain unsupported. This transport is offline groundwork and does not change network state.

## M6 host-wide session lease primitive

`HostSessionLease` opens one fixed `llm_interceptor.session.lock` file relative to a caller-supplied trusted directory descriptor. It uses `openat` with `O_NOFOLLOW`, `O_CLOEXEC`, and `O_NONBLOCK`, validates that the directory is owned by the effective UID with mode `0700`, and validates that the opened lock is an effective-UID-owned regular file with mode `0600` and exactly one link. It then takes a nonblocking exclusive `flock`. Contention and unsafe/open/lock failures have separate status codes. The move-only RAII object releases the advisory lock and closes its descriptor; it never unlinks the file, avoiding pathname replacement races.

This primitive coordinates cooperating processes only when every instance uses the same canonical private directory inode. It does not issue session tokens, authorize a caller, verify a session snapshot, or implement recovery. Production must supply the same already trusted, root-owned private directory descriptor to every helper and must not leak the lock descriptor to child processes. `O_CLOEXEC` prevents inheritance across `exec`, but a forked child that does not exec can still share the open-file-description lock. Tests use only owned private temporary directories; this primitive is not wired into `SystemOperations`, the GUI, or a privileged service.

## M6 durable PF-anchor recovery journal primitive

`PfRecoveryJournal` duplicates a caller-supplied trusted private directory descriptor and serializes operations with a fixed private guard file using a nonblocking exclusive lock. Its fixed journal contains only a schema version, a session ID validated with the `SessionSnapshot` grammar, the derived `llm_interceptor/<session-id>` anchor, and `cleanup_needed` phase; it does not store IP addresses, prompts, tokens, or arbitrary rule text. `persistCleanupNeeded()` is the required durable step before attempting any PF command that may apply. It writes a mode-0600 temporary file with exclusive/no-follow creation, fsyncs the file, atomically renames it over the journal, and fsyncs the directory. Any existing record, including one with the same session ID, blocks a new persist because this primitive has no generation proof to distinguish a restarted session; malformed/unsafe files also fail closed. Failures before rename preserve the prior record. If directory fsync after rename fails, the result is `durability_uncertain`; callers must stop before the PF command and treat the cleanup obligation as retained.

`clearAfterVerifiedCleanup()` requires an exact matching session ID and is only for callers that have independently verified cleanup. It unlinks the journal and fsyncs the directory. If that fsync fails, it reports `durability_uncertain`, not a confirmed durable clear; the runtime namespace may be missing the record while a stale cleanup-needed record may reappear after restart. Since cleanup was already independently verified, retrying cleanup is safe. This journal represents only scoped PF-anchor cleanup ownership; it does not recover PF references, ARP changes, forwarding settings, or other resources. It is offline and unwired from GUI, `SystemOperations`, and live PF commands.

## Injected operations and ownership

The backend is borrowed and must outlive `NetworkSession`; all session methods/getters belong to its QObject thread. Operations return status without throwing. The backend must enforce a single host-wide lease across cooperating helper sessions, not merely a lock in one GUI object. It owns token issuance and must reject stale/nonowned tokens.

Startup acquires an exclusive session lease and fresh preflight, checks interface availability, snapshots forwarding/redirect settings, acquires a PF enable reference, installs the owned anchor, atomically prepares forwarding/redirect suppression, and activates selected-pair ARP. Proxy readiness precedes ARP activation. A mutation attempt is journaled before anchor/ARP operations because an error can include partial effects. Those operations must be idempotent and may touch only resources exclusively assigned to this leased session. Atomic setting operations distinguish Applied, Unchanged, Conflict, and Failed; Failed/Conflict perform no write. Unchanged means the desired value already existed and does not give startup ownership.

Failure triggers rollback using the same retained snapshot and ownership journal. Stop ceases ARP refresh and restores neighbors before dismantling forwarding. It removes the owned anchor before clearing owned states, preventing fresh state creation. Then it conditionally restores changed settings, releases only its PF reference, and releases its lease. An early cleanup failure retains subsequent resources for retry. Concurrent setting conflicts remain explicit CleanupPending state; the helper does not overwrite them. Calls during state-transition signals cannot reenter start/stop.

Compare-and-set is a required atomic backend contract, not a read-then-write shortcut. The fake tests inject a change between inspection and restoration and prove that it survives. Ordinary macOS command-line sysctl reads/writes do not establish this contract; a future adapter needs a validated safe mechanism or must report that capability unavailable. This is an M6 platform limitation, not a verified OS feature.

The watchdog accepts an injected monotonic millisecond clock. A missing heartbeat for 5000 ms, a backwards clock, or interface loss triggers scoped cleanup. `HelperWatchdog` uses a bounded-interval Qt timer without blocking sleeps. Socket transport and scheduler share the callback stored by the dispatcher. A running event loop is required; hosting this scheduler in an installed helper service that survives GUI failure and actual live watchdog behavior remain unverified.

Normal destruction attempts cleanup on the owner thread without emitting lifecycle signals. Failed destruction transfers the exact snapshot/journal to `retainRecovery`, with diagnostics for successful transfer or failed retention. Tests retain it in memory. A future surviving helper service must host and integrate the scheduler, durably persist recovery ownership across process failure, and implement the actual authenticated IPC transport, signing/install, and recovery tooling. Destructor cleanup cannot guarantee recovery after crashes, machine loss, stale neighbors, or backend failure.

## Actual checks and deferred validation

`/sbin/pfctl -n -f docs/m4/example.pf` exited 0 on macOS 27.0.1 arm64 for the documentation-address, nondefault-port example. The tool printed its generic `-f` global-rule warning; `-n` prevented loading. This checks syntax only, not active anchor evaluation, packet delivery, reverse translation, or ownership.

Qt tests use synthetic Ethernet files and fake settings/ARP/PF resources. They cover bounds, malformed/unsupported frames, immutable scope, mismatched readiness, partial startup, repeated cleanup failures, preserved unrelated anchors/state/references, lease exclusivity, atomic conflict handling, watchdog/interface loss, destructor cleanup, and recovery transfer. Live MAC/IP delivery, actual PF state, Wi-Fi ARP compatibility, bypass connectivity, packaging/privileges, and real recovery remain M6.
