# M5 inspection, archives, and replay

The request inspector retains matching POST requests whose bodies are JSON objects. Retention is bounded by both row count and unique body storage. Defaults are 100 records and 8 MiB; the configuration page allows 1–1000 records and 1–256 MiB. Qt's implicitly shared byte arrays let the original request appear in several record fields without copying its payload, so it counts once; a distinct modified body counts separately. Oldest records are removed first when either limit would be exceeded. A single record larger than the byte budget is forwarded normally but is not retained. This is an in-memory inspection limit; it does not change the proxy's independent maximum request body size.

The Requests page shows the retained count, modified count, and retained request-body bytes. **Export sanitized archive** writes JSON Lines records with a format version, request identifier, method, path, response status, request bodies, and modified flag. The exporter recursively redacts common credential fields such as authorization, API keys, tokens, passwords, secrets, cookies, bearer values, and private keys. It also removes audit text, which can contain user-authored values. Query values with credential-like names are redacted. Invalid body bytes are replaced by an explicit redacted placeholder.

Structured field matching cannot recognize secrets embedded in ordinary prompt or message text, or secrets stored under an unusual field name. Review an archive before sharing it. Exported files may contain prompts, model names, and other research content.

**Export sanitized archive** and **Import offline replay** both enforce the same 1000-record and 16 MiB archive limits, so every completed export fits the import limit. The import parser validates each record, applies credential redaction again, discards audit text, and commits the result only if the entire archive is valid. Replay memory is capped at 64 MiB and each body at 16 MiB. A loaded replay appears in the same inspection list and summary; it does not construct a listener or upstream network manager. Starting the live proxy is refused while replay records are loaded. Use **Clear replay** before starting a proxy.

Archive import and export run in the GUI process and are capped at 16 MiB to bound file and parsing work. Live proxy relay and parser work remain on the worker thread. The replay format preserves supported request records, not response bodies or transport-level timing, so it is for offline inspection and repeatable UI review rather than protocol simulation.

The synthetic-load test is configured for 300 sequential requests, 300 retained rows, and a 5 ms GUI heartbeat; the byte-retention scenario uses 2 MiB request bodies with a two-row, 5 MiB budget. These socket-backed measurements were skipped in this runner because loopback binding was denied, so GUI responsiveness under that workload remains unmeasured here. Archive roundtrip/redaction, atomic import bounds, summaries, and replay isolation tests ran successfully.
